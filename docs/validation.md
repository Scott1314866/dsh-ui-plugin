- Host / Client 分离的 TypeScript 严格检查通过。
- 24 项单元及 Harness 注册器测试通过，包含 SDK 版本与行号、公开资料缓存、团队授权拒绝、保密路由、PTC/并行工具、历史来源、状态重放、取消与脱敏导出。
- Chromium 浏览器契约测试通过：真实组件接收受控事件，验证来源更新、历史回合隔离、文件动作、调用详情、配置字段写入、不安全 URL 拦截及原生提交按钮的圆形样式。受控事件仅存在于测试夹具。
- 打包检查确认浏览器使用 Harness ModuleLoader 协议，包中没有预览假对话、公司资料、SDK、个人目录配置或凭据。

## 实际 Harness 安装与模型链路

将 `.tgz` 安装到独立 `0.2.1-rc.2` profile，并作为正常 bundle 加载，而非使用临时 `--patch` 注入。以下均在实际 Harness 网页中完成：

1. 官方品牌槽位显示西恩标识，原生发送按钮实测 40 × 40 px、圆形。未添加旧预览中的证据台/评测全局入口。
2. 「资料连接」将芯片、SDK 版本与本机 SDK 目录写入 Host，返回保存成功；密钥输入框不回显已保存值。
3. 使用本机已配置的 DeepSeek 凭据、非思考模式及只读会话，提交 UART SDK 验收问题。真实模型依次调用 `skill`、`hpm_search`、`hpm_read`。
4. `hpm_search` 查询 `uart_init`、SDK `1.13.0`，返回 3 条来源；读取 `samples/drivers/uart/uart_9bit/src/uart_9bit.c` 的 L40–95 后，相同来源由“搜索命中”升级为“已读取”。其余两条保留搜索状态。
5. 会话状态实际经历工作、检索、回答并收到 `turn/end.reason=completed`，历时约 23 秒。刷新网页后仍恢复完成状态与 3 条来源。
6. 「调用链」显示 `skill`、`hpm_search`、`hpm_read` 的实际记录；点击源码卡通过原生资源查看器打开了完整 UART C 文件。
7. 发起另一条只读问题，点击原生「停止生成」。Host 确认后显示“已停止”，约 0.2 秒；刷新后保留停止状态。最新回合没有沿用上一回合的 3 条来源。

实际页面未发现客户端异常。没有改动用户原有桌面 profile、旧 Web profile、SDK 或 RAG 后台。验证产生的会话、凭据、个人配置、启动口令与原始日志均仅位于被 Git 忽略的本地验证目录。

## 0.1.1 / DSH 0.2.1-rc.3 兼容性补验

- `engines.dsh` 与全部 DSH peer 范围显式接受 `0.2.1-rc.2 || 0.2.1-rc.3`，没有关闭引擎检查；开发 API 和锁文件更新到 `rc.3`。
- 对照新版本的品牌槽位、会话、输入框、标签页和配置接口后，Host / Client 类型检查、24 项测试、浏览器契约测试及打包检查均通过。
- 将 `0.1.1` 安装到独立的真实 `rc.3` profile 并启动，未出现引擎不兼容或客户端加载错误。
- 在真实网页中保存 SDK 配置、以只读权限提问；模型调用资料工具，得到 3 条 SDK 来源，其中 1 条升级为已读取，原文范围为 L60–77。
- 刷新后恢复完成状态与 3 条来源；点击 C 源码卡能打开原生查看器。
- 另起一轮后点击原生停止按钮，Host 确认停止；刷新后恢复 `stopped`，未发现客户端异常。
- CI 改为分别安装 `rc.2` 和 `rc.3` 的 API 集合，独立执行类型、工具、界面和打包检查。
- 结构尺寸图和本地设计预览继续排除在插件包及仓库之外。
