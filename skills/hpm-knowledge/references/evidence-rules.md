# Verify evidence

Search status `search_hit` means discovery only. A successful read changes it to `read`, which records retrieval, not automatic correctness or chip/version verification. `unconfirmed` applicability must remain visible until evidence resolves it.

For SDK code, check the actual VERSION, example and accompanying instructions, initialization, declaration/implementation when relevant, and board setup. Use current local file bytes, content digest, true 1-based lines and Git commit/dirty state when available. Label local modifications as local. A requested/local version conflict must be reported; never silently relabel files.

For tables retain headers, units, footnotes, conditions, and min/typ/max columns. Physical PDF pages are 1-based and independent of printed page labels. Read adjacent pages for split tables; uncertain cross-page relationships require original preview and an explicit uncertainty note. Text-only PDF extraction does not verify column alignment.

Truncated results include continuation. Read the missing portion, a full function/file or adjacent pages as needed; provider truncation without a cursor requires another reader or more specific source. Cached content must carry its actual fetch date. Source unavailability does not establish a negative engineering claim.

Keep each source's chip/version attribution during comparisons. Identify cross-source inferences and conditions not yet verified. Never present uncalibrated similarity percentages.
